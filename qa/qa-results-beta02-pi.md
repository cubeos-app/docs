### P0: App install bind mount directories not created

**Symptom:** ntfy app installed via appstore, workflow reached step 8 (wait_convergence), but Docker service stuck at 0/1 replicas.

**Root cause:** Docker Swarm rejects the service because bind mount source paths don't exist:
```
invalid mount config for type "bind": bind source path does not exist:
  /cubeos/apps/big-bear-ntfy/appconfig/ntfysh_cache
```

**Details:** The compose file generated by the remap_volumes step uses relative bind mount source names (`ntfysh_cache`, `ntfysh_config`). Docker Swarm resolves these relative to the working directory. The `create_dirs` activity creates `appconfig/` and `appdata/` but does NOT create subdirectories for individual bind mount sources.

**Affected file:** `api/internal/flowengine/activities/docker.go` or `api/internal/flowengine/activities/infra.go` — the create_dirs or remap_volumes activity.

**Fix needed:** After remapping volumes, scan the compose file for `type: bind` mounts and ensure each `source` directory exists (mkdir -p).
